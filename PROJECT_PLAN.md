# Utah Startup State — Project Plan

**Event:** Utah GOED AI Builder Day Hackathon
**Deliverable:** Production-ready platform for the Startup State initiative
**Customer:** Utah Governor's Office of Economic Development (GOED)
**Window:** 48 hours, plus handoff documentation

---

## 1. Executive Summary

We are building a single Next.js application that the State of Utah can take over and run for years. It contains three product surfaces sharing one CMS, one database, and one auth system:

1. **The Founder's Navigator** — guided intake flow that produces a personalized action plan
2. **The Resource Guide** — natural-language AI chat over the full resource catalog
3. **The Utah Startup Map** — interactive map with self-service company profiles

We are optimizing for two simultaneous outcomes:

- **Win the weekend.** A polished, working prototype demoable on Sunday with all six personas validated.
- **Be production-ready for GOED.** Boring, portable infrastructure choices. No vendor lock-in. A handoff runbook a state contractor can follow without us.

**Non-negotiables from the spec:**
- Personalized experience that adapts to user context
- Easily updatable without a developer (real CMS, not a Sheets sync)
- Self-service company profiles with lightweight verification
- Production-quality UI worthy of investors

**Strategic call:** Build the Navigator + Resource Guide deeply (shared data layer, both AI-powered). Map gets a strong MVP if Workstream E stays on schedule. Depth beats breadth — judging weights Usability (30%) + Design (25%) = 55% on polish.

## 2. Product Scope

### 2.1 The Founder's Navigator

A 90-second guided journey from "I have an idea" to "here are your next 3 moves."

**Flow:**
1. Landing — single hero question with 4-5 visual entry points
2. Adaptive intake — 3-5 branching questions (location, industry, stage, blocker, demographic eligibility)
3. Personalized plan — prioritized actions, qualifying programs, people to contact, with citations
4. Save/share — email plan, return via link
5. Optional — "Ask follow-up questions" handoff to Resource Guide with intake context preserved

**Acceptance criteria:** All 6 personas in the spec produce meaningfully different, useful plans. This is verifiable on `/demo` page.

### 2.2 The Resource Guide (AI Chat)

Open-ended natural-language Q&A over the resource catalog. Composes with the Navigator — after the intake plan, users can keep asking questions with context preserved.

**Behavior contract:**
- Every claim cites the source resource (link to startup.utah.gov page)
- Refuses to invent resources — if no match, says so and suggests adjacent options
- Personalization-aware — uses Navigator intake context if available
- Streamed responses
- Rate-limited per IP and globally

### 2.3 The Utah Startup Map

Interactive visual map of every business in the Utah ecosystem. Two audiences: founders looking for partners/customers/employers, and investors evaluating Utah's ecosystem.

**Required fields per company:** name, website, employees, sector, year founded, LinkedIn, description, address, hiring status, job postings, photo gallery.

**Self-service:**
- Anyone can submit a new company (lands in `pending` moderation queue)
- Existing listings can be claimed via magic link to email matching the company's website domain
- Claimed-listing edits auto-publish but log a diff for GOED review

**Filters:** sector, size, stage, hiring status, location.

## 4. Technology Stack (Locked)

| Layer | Choice | Reason |
|---|---|---|
| Framework | Next.js 15 (App Router) | RSC, route handlers, deployable to Vercel and Docker equivalently |
| UI | Tailwind + shadcn/ui (Radix) | Production-quality components, accessibility built in |
| CMS | Payload CMS (self-hosted) | Code-first, embedded in Next.js, REST API, built-in admin UI and auth |
| Database | Postgres 16 + pgvector | Single store for content, vectors, conversations |
| Object storage | Cloudflare R2 (S3-compatible API) | Cheap egress, swappable for AWS S3 in production |
| Auth | Payload's built-in auth | Email/password for GOED staff; magic-link for company claimants |
| AI orchestration | Vercel AI SDK (`ai` + `@ai-sdk/anthropic`) | Streaming, `useChat` hook, native Anthropic support |
| LLM | Claude Sonnet 4.6 (`claude-sonnet-4-6`) | Best balance of quality, latency, cost for this use case |
| Embeddings | OpenAI `text-embedding-3-small` | Cheap, 1536-dim, Postgres-friendly |
| Rate limiting / cache | Upstash Redis | Serverless, REST-accessible from edge |
| Maps | Mapbox GL JS | Generous free tier, polished default styling |
| Email | Resend | Simple API for magic links and plan-share emails |
| Observability | Sentry + Vercel Analytics | Errors and traffic |
| CI/CD | GitHub Actions | Standard, portable |
| IaC | Terraform | Documents the production target for handoff |
| Container runtime | Docker | Decouples deployment from Vercel for handoff |

**Explicit rejections:**
- No LlamaIndex / LangChain — retrieval is ~20 lines of SQL at our scale
- No GraphQL — REST only
- No Vercel-edge-runtime-only code paths — must run on plain Node for handoff portability
- No client-side database access — all reads/writes through Next.js routes

## 6. Data Model

All collections live in Payload, backed by Postgres. Definitions are abbreviated.

### Resources
```ts
{
  title: string,                     // required
  slug: string,                      // required, unique
  description: richText,             // required
  url: string,                       // source link on startup.utah.gov
  tags: {
    stage: ['idea','early','growth','scaling']<multi>,
    industry: string<multi>,
    geography: ['statewide','urban','rural','county-specific'],
    counties: string<multi>,
    demographic: ['veteran','women','minority','rural','any']<multi>,
    resourceType: ['capital','education','mentorship','networking','legal','other']<multi>,
  },
  eligibility: richText,
  // Auto-populated by background job
  syntheticQueries: string[],        // 8-12 founder-language questions
  embedding: vector(1536),           // pgvector column
  embeddingUpdatedAt: timestamp,
}
```

Hooks: `afterChange` enqueues `embedResource` job (which generates synthetic queries + embedding).

### Companies
```ts
{
  name: string,
  slug: string,                      // unique, used in URLs
  website: string,                   // domain used for claim verification
  description: text,
  sector: string,
  stage: enum,
  employeeCount: enum,               // ranges, not exact for privacy
  yearFounded: number,
  location: { lat, lng, city, county, address },
  linkedin: string,
  hiringStatus: ['actively','occasionally','not'],
  jobPostings: array<{ title, link, department }>,
  photos: relationship<media>,
  status: ['pending','published','archived'],
  claimedBy: relationship<users>?,   // null until claimed
  lastEditedAt: timestamp,
  diffLog: array<{ user, timestamp, changes }>,  // audit for moderation
}
```

Hooks: `beforeChange` sets `status: 'pending'` for unauthenticated submissions; `afterChange` writes diff log entries.

Access control: anonymous users can only `create` (status forced to pending). Claimants can `update` their own claimed companies. Admins can do anything.

### Users
```ts
{
  email: string,
  role: ['admin','staff','claimant'],
  associatedCompany: relationship<companies>?,  // for claimants
}
```

Two auth flows:
- Admins/staff: standard email/password login at `/admin`
- Claimants: magic link sent to address matching `claimedCompany.website` domain

### Conversations
```ts
{
  sessionId: string,                 // anonymous client-generated
  messages: array<{ role, content, timestamp, citations }>,
  intakeContext: json?,              // copy of Navigator intake if present
  retrievedResources: array<{ resourceId, score }>,
  feedback: { thumbsUp: boolean, comment: string }?,
  createdAt, expiresAt,              // 30-day default retention
}
```

Used for analytics dashboard and quality monitoring.

### Plans
```ts
{
  shareSlug: string,                 // unguessable, used in /plan/[slug] URL
  intake: json,                      // user's answers
  generatedPlan: richText,
  recommendedResources: array<relationship<resources>>,
  emailedTo: string?,
  createdAt, expiresAt,              // 90-day default
}
```

## 8. Production Concerns & How We Address Them

| Concern | Mitigation |
|---|---|
| Embedding latency on save | Background job (Payload jobs queue). Admin UI returns instantly. |
| Failed embeddings | Job retries with exponential backoff. Failures surface in admin. |
| Anthropic API cost runaway | Hard daily cap on chat endpoint. Alerts at 50/80/100% of budget. Cache common queries (embedding + response) in Redis. |
| Chat abuse / scraping | Per-IP rate limit (20 req/min) + global daily cap. Cloudflare Turnstile on first message of a session. |
| Company self-service abuse | New submissions land in `pending`. Edits to claimed listings auto-publish but write a diff log. Moderation queue in admin UI. |
| Magic link spoofing | Verify email matches the company's website domain. Single-use tokens with 15-min expiry. |
| Section 508 / WCAG 2.1 AA | shadcn/ui (Radix primitives accessible by default). axe-core in CI. Manual keyboard nav check before demo. |
| Privacy | Chat conversations log with 30-day retention by default. Privacy notice in chat UI. PII fields from intake are *not* logged. Retention configurable via env var. |
| Backups / DR | Neon point-in-time recovery (built-in). Daily logical dumps to R2 via cron. Documented restore procedure. |
| Observability | Sentry for errors. Custom Payload dashboard showing chat volume, top queries, weak retrievals, token spend. |
| Staging environment | Separate Neon branch + Vercel preview env. GOED previews content changes before publishing. |
| Secrets | Vercel env vars (encrypted). 1Password vault for the team. No secrets in git. |
| CSP / security headers | Strict CSP, HSTS, X-Frame-Options via `next.config.js` headers. |
| Handoff portability | All code runs in Docker. No Vercel-edge-runtime-only APIs. Standard Postgres. |

### 14.2 Synthetic query generation prompt (v1 draft)

Lives in `lib/ai/prompts/synthetic-queries.ts`. Iterate Saturday morning.

> You are helping Utah founders find the right state resource. Below is a description of one program available through Utah's Startup State initiative.
>
> Generate 10 questions a real founder might ask in their own words that this program would answer. Vary the phrasing, urgency level, and specificity. Use natural founder language — not government language. Cover questions about eligibility, the problem being solved, life situations, and adjacent concerns a founder might have. >
> Return a JSON array of strings.

> **Rules:**

> 3. If user intake context is provided (location, stage, demographic), tailor your answer to that context.

> **User intake (if any):** {{intake}}
