# Internationalization (i18n)

How to add or enable a locale for this app (aligned with [PROJECT_PLAN.md](../PROJECT_PLAN.md)).

## 1. Routing

Add the locale code to [`i18n/routing.ts`](../i18n/routing.ts) (`locales` array). Keep `defaultLocale` as the fallback when negotiation does not match.

## 2. Message catalog

Create `messages/<locale>.json` (ICU message format via next-intl). Copy structure from `messages/en.json` and translate keys.

## 3. Convex catalog content (later)

Per-resource text lives in `resourceTranslations` (not in these JSON files). Add rows per resource for the new locale, then run embedding jobs as documented in the Convex handoff (see PROJECT_PLAN §807–811).

## 4. Verification

- Visit `/<locale>/` and smoke-test UI strings.
- Confirm the locale appears in the header switcher (switcher lists every entry in `routing.locales`).

## 5. Environment variables

If you document public locale defaults (e.g. `NEXT_PUBLIC_SUPPORTED_LOCALES`), keep them in sync with `i18n/routing.ts`.

`NEXT_PUBLIC_TIME_ZONE` overrides the default IANA zone (`America/Denver`) used by next-intl for formatting — see [`i18n/time-zone.ts`](../i18n/time-zone.ts).
